# Codex 实现任务模板

> 每次只让 Codex 完成一个可独立验证的小任务。不要直接要求生成完整课程设计。

## 1. 任务名称

`Clip XX / Task XXA：<模块名称>`

## 2. 应用背景

说明该模块在完整机器人系统中的位置：

- 上游模块；
- 下游模块；
- 对应真实应用环节；
- 不实现该模块会导致什么问题。

## 3. 本次唯一目标

用一句话说明本次只解决什么。

示例：

> 实现 ManiSkill 自定义环境的 reset、observation 和 success 判定，不实现专家控制器、训练代码和视觉输入。

## 4. 输入与输出契约

### 输入

| 字段 | shape / 类型 | 单位 | 坐标系 | 来源 |
|---|---|---|---|---|
|  |  |  |  |  |

### 输出

| 字段 | shape / 类型 | 单位 | 坐标系 | 使用者 |
|---|---|---|---|---|
|  |  |  |  |  |

## 5. 允许修改的文件

```text
06-capstone-project/implementation/...
```

明确禁止修改无关 lecture、实验或配置。

## 6. 实现要求

- 代码结构；
- 配置方式；
- 类型提示；
- 错误处理；
- 日志字段；
- 随机种子；
- 版本兼容性；
- 不允许使用的捷径或仿真特权信息。

## 7. 必须编写的测试

至少包含：

- 正常输入；
- 边界输入；
- 非法输入；
- shape 或单位错误；
- 固定随机种子的可复现性；
- 一个已知故障的防回归测试。

## 8. 验收命令

```bash
# 安装或环境检查

# 单元测试

# 最小运行

# 结果检查
```

Codex 必须返回真实可执行命令，不得只写伪代码。

## 9. 预期产物

- 新增或修改文件列表；
- 每个文件职责；
- 运行命令；
- 测试结果；
- 已知限制；
- 仍待人工决定的问题。

## 10. 禁止事项

- 不静默改变任务定义；
- 不删除失败检查以让测试通过；
- 不降低 success 标准伪造提升；
- 不使用测试集选择模型；
- 不把仿真真值混入可部署观测；
- 不一次性重构无关代码；
- 不在没有说明的情况下升级依赖；
- 不用占位实现冒充完成。

## 11. 用户接管检查

实现完成后，用户必须填写：

- 我能否画出调用链；
- 我能否解释每个关键张量；
- 我实际运行了哪些命令；
- 我主动修改了什么；
- 我制造并诊断了什么故障；
- 哪个输入在真实系统中最难获得；
- 下一步实验由什么证据驱动。
