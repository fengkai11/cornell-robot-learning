# Clip 01：ManiSkill 环境与传统控制基线

## 1. 本阶段目标

建立一个可测试、可解释、可重复的装配环境，并用非学习方法完成最小闭环。此阶段的核心不是“把环境做得复杂”，而是确认任务定义、动作接口、成功条件和日志系统可信。

## 2. 环境最小版本

第一版采用：

- 单机械臂；
- 单插销或单齿轮；
- 单目标孔位或轴；
- 状态观测；
- 末端增量位姿动作；
- 低速、无危险接触；
- 固定相机仅用于录制，不进入策略。

建议观测：

```text
qpos
qvel
tcp_pose
object_pose
target_pose
object_to_target_pose
insertion_depth
contact_or_force_proxy
phase_id
previous_action
```

建议动作：

```text
[dx, dy, dz, droll, dpitch, dyaw, gripper]
```

动作必须明确：

- 坐标系；
- 单位；
- 是否归一化；
- 单步最大幅度；
- 控制频率；
- 底层控制器类型。

## 3. 环境生命周期

你必须读懂并能画出：

```text
register_env
→ gym.make
→ _load_scene
→ _initialize_episode
→ reset
→ _get_obs_extra
→ policy/controller action
→ step
→ evaluate
→ reward / terminated / truncated
```

重点区分：

- `_load_scene`：创建长期存在的机器人、物体和场景资源；
- `_initialize_episode`：对每个 episode 设置随机初始状态；
- `evaluate`：计算任务结果，不等同于奖励；
- `terminated`：任务成功或不可继续；
- `truncated`：达到时间或外部限制。

## 4. 成功条件

成功条件至少包含：

- 横向位置误差；
- 轴向姿态误差；
- 插入深度；
- 是否保持稳定若干步；
- 是否未触发安全条件。

不要只使用单一插入深度，否则策略可能通过倾斜挤压或错误接触获得“成功”。

## 5. 传统控制基线

使用状态机完成：

```text
RESET
→ PRE_APPROACH
→ ALIGN
→ DESCEND
→ INSERT
→ VERIFY
→ SUCCESS / RETRACT / FAILURE
```

基线可以使用仿真真值目标位姿，但必须显式标记为 privileged baseline。它的作用是：

- 验证环境是否可完成；
- 生成初始专家轨迹；
- 建立成功率和周期时间上界；
- 暴露任务中真正难以建模的环节。

## 6. Codex 实现任务

让 Codex 分四个小任务实现，不要一次生成完整项目。

### Task 01A：环境骨架

- 创建自定义 ManiSkill 环境；
- 加载机器人、工作台、对象和目标；
- 完成 reset、observation、evaluate；
- 编写 reset 一致性和 observation shape 测试。

### Task 01B：动作接口

- 实现末端增量动作封装；
- 加入动作裁剪、工作空间限制和单位测试；
- 保存实际执行动作与策略原始动作。

### Task 01C：状态机专家

- 实现传统抵近、对准和插入；
- 每个 phase 有独立进入与退出条件；
- 失败时后退并记录失败码。

### Task 01D：评测与可视化

- 批量运行多个随机种子；
- 输出成功率、周期、误差和失败分布；
- 绘制 TCP 轨迹、插入深度和接触信号；
- 录制少量成功与失败视频。

## 7. 代码阅读清单

你必须优先阅读：

1. 环境注册位置；
2. reset 随机化代码；
3. observation 拼接顺序；
4. 动作缩放与坐标系转换；
5. success 判定；
6. phase 状态转换；
7. 日志写入位置。

对每个张量写出 shape 和每一维的物理含义。

## 8. 主动修改任务

至少完成两项：

- 将孔位随机范围扩大一倍；
- 将动作步长减半；
- 增加成功稳定保持步数；
- 修改姿态误差阈值；
- 将控制频率从一种设置改为另一种设置；
- 将真值目标位姿加入可控噪声。

修改前先预测结果，修改后用统一评测验证。

## 9. 故障注入

主动制造并诊断：

- 四元数顺序错误；
- 毫米和米单位混淆；
- 动作坐标系从 TCP 误写为 base；
- reset 后对象状态未刷新；
- 成功条件只看插入深度；
- 状态机在两个 phase 间抖动。

每个故障都要留下：症状、根因、最小修复和防回归测试。

## 10. 应用映射

列出每个仿真输入在真实系统中的来源：

| 仿真量 | 真实来源 | 风险 |
|---|---|---|
| `qpos/qvel` | 编码器 | 延迟、滤波 |
| `tcp_pose` | 正运动学 | TCP 标定误差 |
| `target_pose` | 相机与位姿估计 | 标定、遮挡、噪声 |
| `contact_force` | 力传感器或电流估计 | 偏置、带宽、漂移 |
| `insertion_depth` | 几何估计或编码器积分 | 累积误差 |

## 11. 阶段产物

- 可注册环境；
- 单元测试；
- 传统控制器；
- 100 个以上 episode 的基线结果；
- 成功和失败视频；
- 仿真特权信息清单；
- 至少两项主动修改和两项故障诊断记录。

## 12. 通过门槛

- 固定初始条件下专家成功率接近 100%；
- 随机化条件下结果可复现；
- observation 和 action 的物理含义能够逐维解释；
- success 不可被明显投机；
- 所有失败有分类；
- 能说明从仿真真值切换到真实传感器时最先出现的三个问题。
