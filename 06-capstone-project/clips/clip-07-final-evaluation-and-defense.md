# Clip 07：最终评测、报告、演示与答辩

## 1. 本阶段目标

将整个课程设计从“若干能运行的代码”收敛为一个有明确研究问题、可复现实验、工程结论和真实应用判断的完整项目。

最终评价不只看最高成功率，而看：

- 问题是否定义清楚；
- 对照是否公平；
- 失败是否被解释；
- 结论是否超出证据；
- 系统是否具有真实部署路径；
- 用户是否真正理解 Codex 生成的实现。

## 2. 最终研究问题

从以下方向选择一条主问题，其他算法作为支撑：

### 方向 A：混合系统

> 在接触丰富的装配任务中，传统控制、模仿学习和 Residual RL 的分工是否比单一端到端策略更可靠？

### 方向 B：数据闭环

> 在相同专家标注预算下，DAgger 定向纠正是否比增加普通示范更有效？

### 方向 C：轻量 VLA

> 在有限算力和有限数据条件下，预训练轻量 VLA 的参数高效适配是否比从头训练语言条件策略具有更好的数据效率和组合泛化？

### 方向 D：Sim2Real 准备

> 目标位姿噪声、延迟和接触观测误差如何影响不同策略，混合系统能否降低对仿真特权信息的依赖？

不要同时把四个问题都当作论文主贡献。

## 4. 统一指标

### 4.1 任务表现

- 成功率和置信区间；
- 完成时间；
- 最大与累计接触力；
- 横向和姿态误差；
- 卡滞率；
- 恢复成功率；
- 重试次数；
- 安全事件。

### 4.2 学习效率

- 专家 episode 数；
- 专家介入次数；
- 环境交互步数；
- 训练时间；
- 达到目标成功率所需数据；
- 多随机种子方差。

### 4.3 工程资源

- GPU 显存峰值；
- 推理延迟；
- 策略更新频率；
- 仿真速度；
- 模型大小；
- 部署依赖；
- 数据存储规模。

### 4.4 泛化与应用

- 未见初始状态；
- 未见对象/目标组合；
- 指令改写；
- 标定偏置；
- 延迟和丢帧；
- 摩擦与间隙变化；
- 特权信息删除后的性能。

## 5. 公平比较规则

- 使用相同测试 episode 和随机种子；
- 使用相同动作限制和安全过滤器；
- 明确训练数据和交互预算；
- 不为某方法单独放宽 success 条件；
- 模型选择不能使用最终测试集；
- 报告失败的随机种子；
- 超参数搜索预算需要说明；
- 训练失败不能只挑最好一次结果。

## 6. 失败案例要求

最终报告至少分析五类失败，每类包含：

1. 现象；
2. 首个异常时刻；
3. 可能原因排序；
4. 支撑证据；
5. 排除过的原因；
6. 最小修复；
7. 修复后的回归实验；
8. 真实系统中可能造成的影响。

建议至少覆盖：

- 感知或目标位姿误差；
- BC 分布偏移；
- 奖励投机；
- phase 切换错误；
- 语言被忽略；
- 策略延迟或 OOM；
- 接触卡滞和恢复失败。

## 7. 最终报告结构

建议报告结构：

1. **Abstract**：问题、方法、最重要结果和限制；
2. **Application Motivation**：真实应用和验收需求；
3. **Problem Formulation**：状态、观测、动作、动力学、奖励和约束；
4. **System Design**：传统控制、学习策略、安全和调度；
5. **Methods**：只介绍实际实验使用的方法；
6. **Experimental Setup**：环境、数据、预算、随机化和指标；
7. **Results**：主要对照和消融；
8. **Failure Analysis**：成功率背后的失败模式；
9. **Deployment Gap**：传感器、标定、延迟、安全和维护；
10. **Industrial and Home Transfer Value**；
11. **Limitations**；
12. **Conclusion and Next Experiment**。

## 8. 五分钟演示视频

推荐时间分配：

```text
0:00–0:30 真实问题与验收目标
0:30–1:10 系统架构与任务分解
1:10–2:00 传统控制和 BC 基线
2:00–2:50 DAgger / Residual RL 的关键改进
2:50–3:40 语言条件或 VLA 实验
3:40–4:20 失败案例和 Sim2Real 退化

```

视频必须包含失败案例，不能只做成功集锦。

## 9. Codex 实现任务

Codex 可负责：

- 汇总实验配置；
- 检查结果文件完整性；
- 生成统一表格和绘图脚本；
- 自动寻找失败 episode；
- 校验 README 命令；
- 生成报告骨架；
- 生成演示视频素材清单；
- 创建可复现实验脚本。

Codex 不应替你决定：

- 哪个结果最重要；
- 失败的根因；
- 是否支持研究结论；
- 工业价值；
- 下一步应改算法、传感器还是任务设计。

## 10. 代码理解答辩

随机抽取一个模块，你必须完成：

- 画调用链；
- 解释核心张量 shape；
- 指出训练与评测入口；
- 说明一个隐含假设；
- 修改一个参数并预测行为；
- 定位一个故障注入；
- 说明真实系统对应接口。

推荐抽查模块：

- 环境 reset 与 success；
- action scaling；
- 数据时间对齐；
- BC normalization；
- DAgger 数据聚合；
- reward 与 termination；
- residual action composition；
- language-task 对齐；
- safety filter；
- state machine transition。

## 11. 最终答辩问题

至少准备回答：

1. 为什么选择这个应用，而不是普通 Pick-and-Place；
2. 哪个环节根本不需要学习；
3. BC 最主要的失败来自哪里；
4. DAgger 增加的数据为什么有效；
5. Residual RL 相比 RL from scratch 缩小了什么搜索空间；
6. 奖励是否使用了仿真真值；
7. 如何证明 VLA 使用了语言；
8. 4060 算力限制怎样影响模型选择；
9. 如果目标位姿偏差 5 mm，系统首先在哪里失效；
10. 真实机器人上第一项验证是什么；
11. 成功率提升是否值得增加系统复杂度；
12. 工业方案怎样迁移到家庭场景。

## 13. 完成标准

课程设计完成时，你应能面对一个新的真实机器人需求，独立完成：

```text
需求澄清
→ 任务形式化
→ 系统拆解
→ 传统基线
→ 数据方案
→ 学习方法选择
→ 仿真实验
→ 失败诊断
→ 安全与部署设计
→ 最小真实验证
```

最终成果不是“学过 BC、RL 和 VLA”，而是建立一套面对真实机器人应用时知道下一步该做什么的工作方法。
