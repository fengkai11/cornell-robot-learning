# Cornell Robot Learning 学习与实践

本仓库以 Cornell University **CS 4756/5756 Robot Learning (Spring 2026)** 为知识主线，记录课程学习、作业分析、ManiSkill 实验、论文阅读、应用驱动课程设计和阶段复盘。

- 课程主页：<https://www.cs.cornell.edu/courses/cs4756/2026sp/>
- 课程教师：Kuan Fang
- 实践平台：ManiSkill（必要时补充 PyTorch、Gymnasium、MuJoCo、LeRobot 等）

> 学习进度不以“看过多少课件”或“生成了多少代码”为标准，而以能否解释、形式化、实现、修改、诊断和验证为标准。

## 项目目标

完成本项目后，应至少形成以下能力：

1. 将机器人任务形式化为状态、观测、动作、策略、动力学、奖励和约束；
2. 判断传统控制、运动规划、模仿学习、强化学习、MPC、VLA 和混合方法的适用边界；
3. 阅读 Robot Learning 论文，识别问题定义、方法假设、实验设计与结论边界；
4. 在 ManiSkill 中复现核心方法，并设计可靠的对照实验；
5. 形成 BC、RL、MPC、VLA 与混合方法的统一评测框架；
6. 分别评价方法的工业落地价值与向家庭机器人迁移的价值；
7. 面对真实机器人应用，能够完成需求定义、系统拆解、数据方案、失败诊断、安全设计和最小真实验证。

## 学习原则

- 先建立整体框架，再进入公式和实现；
- 不把图像直接等同于状态，明确区分 state 与 observation；
- 不默认端到端学习优于控制和规划；
- 每种学习方法至少设置一个传统方法或简单学习方法基线；
- 不把一次成功运行当作算法有效；
- 不使用单一成功率支撑复杂结论；
- 区分感知误差、规划误差、控制误差、策略误差和评价误差；
- 对观点检查假设、遗漏条件和反例，区分事实、推断与待验证假设；
- 每个算法模块都要明确应用环节、真实观测来源、工程约束、失败模式和回退方案；
- Codex 可以生成代码、测试和实验脚本，但用户必须完成代码阅读、主动修改、故障诊断、实验复现和独立解释；
- 课程作业遵守官方学术诚信要求，并记录使用的 AI 与在线资源。

## 官方课程主线

| 阶段 | 核心主题 | 需要建立的能力 |
|---|---|---|
| Fundamentals | Robot Learning、机器人控制、MDP、深度学习 | 任务形式化与基础控制判断 |

## 每讲工作流

### 课前

1. 明确本讲试图解决的问题；
2. 补齐必要前置知识；
3. 提出 3–5 个带着问题阅读的问题；
4. 标出重点页与可暂时略读内容；
5. 说明本讲知识将在课程设计的哪个环节使用。

### 课中

采用统一顺序：

> 问题背景 → 直觉 → 严格定义 → 必要推导 → 算法流程 → 机器人实例 → 实现细节 → 失败模式 → 应用边界

### 课后

每讲形成：

- 一句话概括；
- 核心概念与关键公式；
- 与相邻方法的区别；
- 隐含假设和失败模式；
- 工业价值与家庭迁移价值；
- ManiSkill 实验建议；
- 课程设计 clip 的连接点；
- 未解决问题与掌握度检查。

## AI 辅助实践工作流

课程设计采用“AI 生成，人类接管”模式：

```text
先预测 → Codex 分模块实现 → 阅读接口与张量 → 运行验证
→ 主动修改 → 故障注入 → 复现实验 → 独立解释
```

每个模块至少满足：

- 能画出数据流和控制流；
- 能解释关键类、函数和张量；
- 能独立修改一个关键设计；
- 能制造并诊断一个故障；
- 能说明仿真输入在真实系统中的来源；
- 能用实验结果决定下一步，而不是让 Codex 自动扩展项目。

Codex 单次任务模板见 [`06-capstone-project/templates/codex-task-template.md`](06-capstone-project/templates/codex-task-template.md)。

## 实验纪律

任何重要实验必须先填写 [`03-maniskill-labs/experiment-template.md`](03-maniskill-labs/experiment-template.md)，至少明确：

- 研究问题与待验证假设；
- 环境、任务和随机化设置；
- 状态、观测、动作与控制频率；
- 专家数据或交互数据来源；
- 传统基线、简单学习基线和目标方法；
- 控制变量、评价指标、随机种子；
- 分布内与分布外测试；
- 混杂因素和失败诊断顺序；
- 仿真特权信息与真实传感器映射；
- 安全、回退和部署约束；
- 结论允许覆盖的范围。

课程设计阶段复盘使用 [`06-capstone-project/templates/clip-review-template.md`](06-capstone-project/templates/clip-review-template.md)。

## 掌握度标准

| 等级 | 判断标准 |
|---|---|
| L1 识别 | 知道术语的大致含义 |
| L2 解释 | 能用自己的话准确解释 |
| L3 形式化 | 能写出变量、假设、目标函数和关键公式 |
| L4 实现 | 能独立实现，或审查 AI 生成实现并完成主动修改 |
| L5 验证 | 能设计对照实验、诊断失败并限制结论范围 |
| L6 应用 | 能映射到真实传感器、控制、安全、部署和交付流程 |

核心模块至少达到 L3–L4，重点模块力争达到 L5；课程设计最终应接近 L6。

## ChatGPT 在本项目中的角色

ChatGPT 作为课程导师、学习监督者、实验评审者、研究桥接者和工程判断教练：

- 帮助解释和审查，而不是替代用户理解与判断；
- 对观点进行条件审查，不因为表述合理就直接认可；
- 优先检查实验设计能否验证假设，再检查实现和结果；
- 将课程连接到抵近、抓取、搬运、放置、接触、装配和异常恢复任务；
- 审查 Codex 生成代码的接口、隐含假设、测试和真实部署差距；
- 同时评价工业价值与向家庭场景迁移的价值；
- 对明显偏离课程主线的问题进行标记，必要时转入其他项目讨论。
